# 部署与运行

## 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17+ | 本机实测 18.0.2.1 |
| Maven | 3.9+ | 本机在 `C:\maven`、`D:\maven` |
| MySQL | 8.x | 本机 8.0.41，端口 3306 |
| Node.js | 18+ | 仅用于跑调试工具（模拟器 / 知识库生成），运行应用不需要 |

## 配置

配置在 `src/main/resources/application.yml`，全部可用环境变量覆盖。

### 必填：主密钥

```powershell
# 生成一个 32 字节 Base64 主密钥
$env:LIFELINE_MASTER_KEY = (openssl rand -base64 32)
```

> ⚠️ **主密钥必须固定并妥善保管。** 更换或丢失会导致已登记的 `secretKey` 全部无法解密，
> 只能让企业重新登记。未配置时应用会启动但生成临时密钥并打印警告，
> 此时登记的凭证重启后即失效，**只能用于本机联调**。

### 必填：数据库口令

口令**没有默认值**，禁止写进仓库：

```powershell
$env:LIFELINE_DB_USER     = 'root'
$env:LIFELINE_DB_PASSWORD = '***'
```

或复制 `src/main/resources/application-local.yml.example` 为 `application-local.yml`
（已在 `.gitignore` 中）后以 `--spring.profiles.active=local` 启动。

### 可选配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `lifeline.old-platform.base-url` | `http://111.47.65.236:9910` | 老平台地址（**测试地址，非生产**） |
| `lifeline.old-platform.token-param-style` | `query` | 取令牌参数位置：`query` 或 `form` |
| `lifeline.old-platform.connect-timeout-ms` | `3000` | 连接超时 |
| `lifeline.old-platform.read-timeout-ms` | `10000` | 读超时；超时即判定结果未知 |
| `lifeline.signature.param-order` | `sorted` | 签名参数顺序：`sorted` / `given` |
| `lifeline.signature.timestamp-tolerance-seconds` | `300` | 时间戳允许偏差 |
| `lifeline.crypto.master-key` | 空 | 等价于 `LIFELINE_MASTER_KEY` |
| `lifeline.debug.enabled` | `true` | 调试台开关，**生产必须关闭** |
| `lifeline.token.ttl-seconds` | `7200` | 新平台自签令牌有效期 |
| `lifeline.token.old-token-cache-seconds` | `1800` | 老令牌本地缓存时长 |

## 本机联调：不要碰真实老平台

`tools/mock-old-platform.mjs` 是老平台模拟器，可以在**完全不接触真实老平台**的前提下验证全链路。

```powershell
# 1) 启动模拟器（端口 9999）
node tools/mock-old-platform.mjs 9999

# 2) 让新平台指向模拟器
$env:LIFELINE_OLD_BASE_URL = 'http://localhost:9999'

# 3) 启动应用（另开一个窗口）
java -jar target\lifeline-docking.jar

# 4) 跑端到端冒烟测试
node tools/smoke-test.mjs
```

模拟器提供的测试凭证：`mock-ak-0001` / `mock-sk-0001`（**仅本机模拟器使用，不是真实凭证**）。

### 模拟器的失败注入

用于验证异常分支：

```powershell
# 让后续业务请求返回业务失败 code=1
Invoke-RestMethod -Method POST -Uri 'http://localhost:9999/_mock/mode' -Body '{"code":1}'

# 让后续业务请求不响应（触发"结果未知"）
Invoke-RestMethod -Method POST -Uri 'http://localhost:9999/_mock/mode' -Body '{"timeout":true}'

# 恢复正常
Invoke-RestMethod -Method POST -Uri 'http://localhost:9999/_mock/mode' -Body '{}'
```

冒烟测试自带**安全闸**：若目标老平台不是模拟器（没有 `/_mock/received` 端点），
脚本会直接中止，避免把测试数据推到真实老平台。

## 常见故障

| 现象 | 原因与处理 |
| --- | --- |
| 启动报 `Access denied for user` | 没设 `LIFELINE_DB_PASSWORD` |
| 启动日志出现「未配置 master-key」警告 | 没设 `LIFELINE_MASTER_KEY`，凭证重启后失效 |
| 接口报「secretKey 解密失败」 | 主密钥被更换，需企业重新登记凭证 |
| 所有请求都是 `UNKNOWN` | 老平台地址不通或超时，检查 `base-url` 与网络 |
| 所有请求都是 `REJECTED_OLD` | 老平台业务校验未过，查 `old_response` 列 |
| `stored_count=0, duplicate_count>0` | `lsh` 已存在，属预期判重行为 |
| 请求返回 401 | 新平台令牌缺失/过期，或签名校验失败 |

## 排障取数

数据库里已经保存了排障所需的全部信息：

```sql
-- 某次请求：原始报文 + 老平台原始响应
SELECT raw_body, old_response, old_platform_code, status, message
FROM docking_request_record WHERE record_id = '<id>';
```

配合[上收数据页](http://localhost:8080/records.html)的「详情」按钮可以直接查看。

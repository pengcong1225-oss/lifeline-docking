# 验证记录

记录**已经验证过**的内容与验证方式，避免重复劳动，也避免把未验证的东西当成已验证。

> 所有验证均在**本机 + 老平台模拟器**上完成，**未向真实老平台推送任何数据**。

## 验证方式

两套互补的自动化验证：

| 层次 | 命令 | 规模 | 覆盖 |
| --- | --- | ---: | --- |
| 单元测试 | `mvn -o test` | 31 项 | 加解密、签名、令牌、路由、接口清单、老平台响应解析 |
| 端到端冒烟 | `node tools/smoke-test.mjs` | 40 项断言 | 凭证 → 取令牌 → 推送 → 留存 → 入库 → 转发 → 状态判定 |

冒烟测试带**安全闸**：若目标老平台不是模拟器，脚本直接中止。

## 已验证清单

### 凭证管理

| 项 | 结果 |
| --- | :---: |
| 登记凭证并落库 | ✅ |
| 企业名中文 UTF-8 往返正确 | ✅ |
| 响应只回显密钥尾号，不含明文 | ✅ |
| 列表接口不含密文字段 | ✅ |
| 用该凭证向老平台成功换取令牌 | ✅ |
| 同一明文两次加密产生不同密文（IV 随机） | ✅ |
| 主密钥不匹配时解密抛错（不返回错误内容） | ✅ |
| 密文被篡改时解密失败（GCM 认证） | ✅ |
| 未配置主密钥时启动并告警，不崩溃 | ✅ |

### 接口清单

| 项 | 结果 |
| --- | :---: |
| 解析出 19 个条目（1 令牌 + 18 业务） | ✅ |
| 18 个业务条目路径全为 `/execute/api` | ✅ |
| 字段数与源文档逐条一致（21/13/12/35/13/15/29/11/26/11/2/8/4/1/7/10/12/7） | ✅ |
| `lifeline_data_batch_acces` 拼写被锁定，不会被"修正" | ✅ |

| 条目 4 与 18 路由重复被固化为测试 | ✅ |
| 每个业务条目都有数据字段与预填示例（调试台不会崩） | ✅ |

### 主链路

| 项 | 结果 |
| --- | :---: |
| 调试台发送 → 留存 → 入库 → 转发 → 老平台 `code=0` → `ACCEPTED_OLD` | ✅ |
| 数据项按 `data[]` 下标逐条入库 | ✅ |
| 模拟老平台确认收到转发数据（证明用的是老凭证换来的令牌） | ✅ |
| 留存保留原始请求体与老平台原始响应 | ✅ |
| 调用者正式链路：`/token` 取令牌 → `/execute/api` 推送成功 | ✅ |
| 重复 `lsh` 被判重跳过、不覆盖、计数正确 | ✅ |

### 失败与安全边界

| 项 | 结果 |
| --- | :---: |
| 老平台业务失败（`code=1`）→ `REJECTED_OLD`，业务码被记录 | ✅ |
| 失败时数据**仍然入库**（留存不受老平台结果影响） | ✅ |
| 老平台超时 → `UNKNOWN`，**不伪装成功** | ✅ |
| 超时时未记录业务码（`old_platform_code` 为 NULL） | ✅ |
| 超时时调用者侧返回 **HTTP 502** 而非 200 | ✅ |
| 非法令牌 → 401 | ✅ |
| 错误签名 → 401 | ✅ |
| 新平台令牌不含 `Bearer ` 前缀 | ✅ |
| 响应中不出现老平台令牌 | ✅ |
| 老平台令牌响应带 `Bearer ` 前缀时能正确剥离 | ✅ |

## 复现步骤

```powershell
# 1) 模拟器
node tools/mock-old-platform.mjs 9999

# 2) 应用（指向模拟器）
$env:LIFELINE_OLD_BASE_URL = 'http://localhost:9999'
$env:LIFELINE_MASTER_KEY   = '<固定的 Base64 32 字节密钥>'
$env:LIFELINE_DB_PASSWORD  = '<本机 MySQL 口令>'
java -jar target\lifeline-docking.jar

# 3) 单元测试
C:\maven\bin\mvn.cmd -o -f pom.xml test

# 4) 端到端冒烟（40 项）
node tools/smoke-test.mjs
```

冒烟测试可重复运行（每次生成不同的 `lsh`），不需要清理数据库。

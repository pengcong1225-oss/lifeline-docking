# FAQ 与排查

## 对接前

### Q：接入到底要改什么？

只改**接口地址**。继续用老平台分配的 `accessKey/secretKey`、原请求路径、原字段、原调用方式。

如果调用者把「令牌地址」和「业务地址」分开配置，**两处都要改成新平台地址**，
但不需要改鉴权代码或业务调用代码。

### Q：为什么 18 个接口看起来是同一个 URL？

源平台的设计就是共用一个 `POST /data-docking-api/execute/api`，
靠报文体里的 `apiCmd` + `apiBody.tag`（必要时加 `apiBody.operationType`）区分。
详见[路由规则与陷阱](03-路由规则与陷阱.md)。

### Q：我怎么知道该填哪些字段？

查[接口清单](02-接口清单.md)找到对应条目，字段逐个列在
`src/main/resources/docking-api-catalog.json` 里；
也可以直接用调试台选接口，会自动生成带字段说明的报文模板。

## 调用时

### Q：HTTP 200 了为什么还说失败？

因为**成功只看响应体里的 `code`**：

```json
{ "code": 0, "msg": "成功", "data": true }   ← 只有这个是成功
{ "code": 1, "msg": "参数错误" }              ← HTTP 200 也是失败
```

### Q：`apiCmd` 是不是写错了？`acces` 少一个 s。

没有错。`lifeline_data_batch_acces` 是**源文档原文拼写**，必须照抄。
改成 `access` 会导致路由失败。代码里有测试锁定这个值。

### Q：token 前面要不要加 `Bearer `？

要加：`Authorization: Bearer <token>`。

但要注意：如果平台返回的 token **自身已经带了** `Bearer ` 前缀，
再拼一次会变成 `Bearer Bearer xxx`。这是源文档记录在案的歧义点，
新平台返回的令牌**不含**前缀。见[阻塞项 3](09-联调阻塞项.md)。

### Q：`operationType` 和 `sjtbzt` 都是 I/D，有什么区别？

- `apiBody.operationType`：**结构层**，决定路由到哪个接口（保存 or 删除）；
- `apiBody.data[].sjtbzt`：**数据层**，表示这一条数据的同步动作（I 新增 / U 更新 / D 删除）。

两者独立，可以组合出现。

### Q：`lsh` 怎么生成？

`dsbm`（地市编码）+ `sjly`（数据来源）+ 业务扩展标识，只允许字母数字，最长 128。
**推送方必须保证唯一**，平台按它做唯一校验。

### Q：经纬度用什么坐标系？

**CGCS2000（大地 2000）**，字段名 `lon`/`jd`（经度）、`lat`/`wd`（纬度）。

## 平台行为

### Q：重复推送同一条数据会怎样？

新平台侧按 `(tag, lsh)` 唯一键**跳过并计数**，不覆盖已有数据（见上收数据页的"重"计数）。

老平台侧的行为**尚未验证** —— 可能报错、忽略或覆盖，需联调确认。

### Q：推送时老平台超时了，我该重推吗？

**暂时不要自动重推。** 此时平台返回 HTTP 502，语义是"结果未知"：
数据可能已写入老平台，也可能没有。老平台的幂等性未经验证，盲目重推可能产生重复数据。

正确做法：先在「上收数据」页按留存 ID 查这次请求的状态与老平台响应，再人工决定。

### Q：数据推给新平台后，老平台还会收到吗？

会。第一版**所有**业务都转发给老平台，由老平台判定成功。
新平台只是在其前面加了鉴权、留存与路由层。

后续按业务类别逐步接管，接管后该类才由新平台自行处理。

## 运维排查

### Q：怎么查某次请求到底发生了什么？

在上收数据页找到记录点「详情」，或直接查库：

```sql
SELECT raw_body, old_response, old_platform_code, status, message
FROM docking_request_record WHERE record_id = '<id>';
```

`old_response` 是老平台的原始响应，排障时最关键。

### Q：状态 `UNKNOWN` 是什么意思？

老平台超时或断线，**结果未知**。平台刻意不报成功也不报失败，避免误导。
需要人工核对老平台侧是否已接收。

### Q：`stored_count=0` 但请求成功了？

说明所有数据项的 `lsh` 都已存在（`duplicate_count` 会显示条数），属预期判重行为。

### Q：启动后所有请求都失败/超时？

1. 看 `lifeline.old-platform.base-url` 是否可达；
2. 看应用日志里取令牌是否成功；
3. 本机联调应先启动 `tools/mock-old-platform.mjs` 并把地址指过去。

### Q：报「secretKey 解密失败」怎么办？

主密钥变了。AES-GCM 无法用新密钥解开旧密文，只能让企业**重新登记凭证**。

所以：`LIFELINE_MASTER_KEY` 必须固定保存，不要随意更换。

### Q：能改 `accessKey` 吗？

不能。更新凭证时 `accessKey` 被锁定，避免与已发放的令牌归属错位。
换个 accessKey 等于换一个凭证，请新建。

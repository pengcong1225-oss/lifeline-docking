# 公共字段约定

18 个业务接口按 `apiCmd` 分成两族，字段约定完全不同，**不要跨族套用**。

| 族 | apiCmd | 接口数 | 公共必填字段 |
| --- | --- | ---: | --- |
| 生命线数据批量接入 | `lifeline_data_batch_acces` | 10 | `lsh`、`dsbm`、`qhbm`、`sjly`、`sjtbzt` |
| 第三方巡检数据接入 | `inspection_third_party_data_access` | 8 | 无 —— 每个接口字段各不相同 |

## 一、生命线批量族（10 个接口）

这 5 个字段在该族**每一个接口**中都存在且必填。

### `lsh` 流水号

| 项 | 值 |
| --- | --- |
| 类型 | string |
| 必填 | 是 |
| 组成 | `dsbm` + `sjly` + 业务扩展标识 |
| 长度 | 最长 128，最短 8 |
| 正则 | `^[a-zA-Z0-9]+$` |

**唯一性**：源文档明确「其他接口按流水号做唯一校验，推送方应保证流水号唯一」。
重复的 `lsh` 行为尚未联调确认，见[联调阻塞项](09-联调阻塞项.md)。

> 注意「最短 8」与正则 `^[a-zA-Z0-9]+$` 是源文档原文。若 `dsbm`(6) + `sjly`(最少 4) 已满足 10 位，
> 短于 8 位只可能在字段缺失时出现。文档中的「最短 0」类约束（如 `dsbm`）看起来是文档生成痕迹，
> 不代表真的允许空值。

### `dsbm` 地市编码

| 项 | 值 |
| --- | --- |
| 类型 | string，最长 6 |
| 取值 | 见[数据字典 · 市州编码表](05-数据字典.md#1-市州编码表--字段-dsbm) |
| 示例 | `420500`（宜昌市） |

### `qhbm` 区划编码

| 项 | 值 |
| --- | --- |
| 类型 | string，最长 6 |
| 取值 | 按《2022 年中华人民共和国县以上行政区划代码》，见[数据字典 · 区划编码表](05-数据字典.md) |
| 示例 | `420502`（宜昌市西陵区） |

### `sjly` 数据来源

| 项 | 值 |
| --- | --- |
| 类型 | string |
| 正则 | `^([0-9A-HJ-NPQRTUWXY]{18}\|[a-zA-Z0-9]{4,20})$` |
| 含义 | 二选一：**企业统一社会信用代码**（18 位）或**拼音首字母简称**（4~20 位字母数字） |
| 示例 | `ycrqqy`（宜昌燃气企业拼音简称） |

> 统一社会信用代码字符集排除了 `I`、`O`、`S`、`V`、`Z`，所以正则里是 `[0-9A-HJ-NPQRTUWXY]`
> 而不是 `[0-9A-Z]`。填错字符会被拒。

### `sjtbzt` 数据同步状态

| 值 | 含义 |
| --- | --- |
| `I` | 新增 |
| `U` | 更新 |
| `D` | 删除 |

正则 `[IDU]`，必填。

### `sszx` 所属专项

在该族 10 个接口中，**只有 4 个**要求 `sszx`（条目 2、3、6、9），取值见
[数据字典 · 专项类别表](05-数据字典.md#3-专项类别表--字段-sszx)，
燃气为 `csaqzx_rq`。具体到某个接口是否必填，以[接口清单](02-接口清单.md)为准。

## 二、第三方巡检族（8 个接口）

这 8 个接口**没有公共字段**，字段完全按业务对象定义：

| 条目 | 路由键 | 字段 |
| ---: | --- | --- |
| 4 | `risk / I` | sszx, riskNumber, title, content, address, reportUserId, reportPersonName, reportTime, lon, lat, zjjRiskCode, zjjRiskCtgFullCode |
| 12 | `inspector / D` | enterpriseUserId, userId |
| 13 | `inspector / I` | orgId, userId, name, cardNumber, phone, lifePhotos, postName, dutyArea |
| 14 | `district / I` | businessId, orgId, name, geom |
| 15 | `district / D` | businessId |
| 16 | `route / I` | orgId, userId, lon, lat, speed, receiveTime, receiveDate |
| 18 | `risk / I` | sszx, riskNumber, title, content, address, reportUserId, reportPersonName, reportTime, lon, lat, zjjRiskCode, zjjRiskCtgFullCode |
| 19 | `riskDispose / I` | riskNumber, disposeUserId, disposeUserName, disposeUserPhone, disposeContent, disposeTime, disposeStatus |

> 条目 4 与 18 的字段列表**完全一致**，这正是
> [重复路由冲突](03-路由规则与陷阱.md#已知的重复路由冲突)的证据。

### 第三方巡检族的类型陷阱

源文档把以下字段声明为 `object`，但**没有给出任何结构说明和示例**：

| 字段 | 出现位置 |
| --- | --- |
| `enterpriseUserId` | 条目 12 |
| `orgId` | 条目 13、14、16 |
| `receiveDate` | 条目 16 |

联调时必须向平台方确认它们是对象、数组还是 JSON 字符串。本项目的调试台对这类字段
预填空对象 `{}`，**不要直接当真实数据发出**。

## 三、坐标与时间

| 约定 | 说明 |
| --- | --- |
| 经度 | `lon` / `jd`，number，**CGCS2000（大地 2000）** 坐标系 |
| 纬度 | `lat` / `wd`，number，CGCS2000 |
| 时间 | 多数为 string，格式 `date-time`；个别为 `date`（如 `sgrq` 施工日期） |
| 时间戳 | `jcsj`（监测时间）为 **integer，毫秒时间戳**，不是秒 |

> `jcsj` 声明为 `integer` 且说明写「格式 int32」，但毫秒时间戳实际会超出 32 位有符号整数范围
> （约 2038 年后的秒级时间戳才溢出，毫秒级现在就远超）。这与源文档的类型标注存在矛盾，
> 联调时需确认平台实际接受什么类型。见[联调阻塞项](09-联调阻塞项.md)。

## 四、两套「操作类型」不要混淆

| 机制 | 位置 | 取值 | 作用 |
| --- | --- | --- | --- |
| `apiBody.operationType` | 报文结构层 | `I` / `D` | **路由**：区分同一 tag 下的保存与删除 |
| `apiBody.data[].sjtbzt` | 数据项层 | `I` / `U` / `D` | **业务语义**：这条数据的同步动作 |

一个请求可能 `operationType=I`（路由到"保存或更新"接口）而数据项里 `sjtbzt=D`（该条是删除）。
两者相互独立。
